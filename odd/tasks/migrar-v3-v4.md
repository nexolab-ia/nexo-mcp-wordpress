# Elementor 4: migrar páginas v3 a elementos atómicos (F5)

Fase F5 del soporte de Elementor 4 (ver `odd/tasks/elementor-v4.md`): convertir una página Elementor clásica (v3) a
elementos atómicos. Rama `feat/migrar-v3-v4` desde `main` (ec01273, v1.3.0).

## Specs

- S1. Pedido: «F5: migrar v3 → v4». F5 en `odd/tasks/elementor-v4.md`: «F5 migrar v3 → v4».
- S2. Decisión de destino: «Copia de trabajo (Recomendado)»: «Escribe en la copia de trabajo de la página. El original publicado no se toca hasta que revisás y publicás la copia, igual que en F3.»
- S3. Decisión de alcance: «Página entera (Recomendado)»: «Convierte todo el árbol v3 de la página en una sola operación.»
- S4. Decisión para widgets sin equivalente: «Se conservan como v3 (Recomendado)»: «Quedan como widgets v3 dentro del árbol migrado. Elementor 4 los sigue mostrando. La respuesta los lista.»
- S5. Decisión de estilos: «Básicos + globales (Recomendado)»: «Tipografía, color, espaciado, fondo y borde, con variantes tablet/móvil. Los colores y tipografías globales del Kit se pasan a variables cuando existan. Lo demás se lista como no migrado.»
- S6. Evidencia previa (exploración, 2026-11-19): Elementor 4.4.1 no trae conversor de widgets v3 a atómicos (sólo `css-converter` de CSS a props). Equivalentes directos: heading → `e-heading`, button → `e-button`, image → `e-image`, divider → `e-divider`, contenedores → `e-flexbox`/`e-div-block`. Con pérdida: text-editor (HTML en línea) → `e-paragraph`; `__globals__`. Sin equivalente: spacer, icon-box, testimonial y la mayoría de los compuestos. Diseño detallado tras T1.
- S8. Decisión para text-editor con formato: «Conservar v3 si tiene formato (Recomendado)»: «Si el texto sólo tiene párrafos y enlaces, se migra a e-paragraph (un nodo por párrafo). Si tiene negrita, listas, etc., queda como text-editor v3 y se lista. No se pierde nada.»
- S7. Diseño (del padre, con la evidencia de T1 en L3-L4):
  - Herramienta `nexo-mcp/migrate-elementor-page` `{id, draft?}` (mismo parámetro que `edit-elementor-section`, L9): migra la página entera (S3) a la copia de trabajo con el mismo camino que `edit-elementor-section` (F3): `WorkingCopy::with_lock`, copia creada o reutilizada, respaldo, `save_tree`, `invalidate_post`; el original publicado no cambia (S2). Mismos permisos que `edit-elementor-section`. Requiere `e_atomic_elements` (`nexo_mcp_elementor_v4_required`). Sin nodos v3 que migrar → `nexo_mcp_nothing_to_migrate` sin escribir.
  - Respuesta: `id` (copia), `draft_of`, `preview_url`, `migrated` (cantidad de nodos v3 convertidos), `kept_v3: [{id, type, reason}]` (S4, S8), `unmapped: [{id, keys: [...]}]` (ajustes v3 no trasladados, S5).
  - Estructura: `section` → `e-flexbox` (fila; `html_tag` → `tag` si está en el enum); `column` → `e-div-block` con `width` en % (`_inline_size` o `_column_size`); `container` flex → `e-flexbox` (`flex_direction`, `flex_justify_content`, `flex_align_items`, `flex_wrap`, `flex_gap` → `flex-direction`, `justify-content`, `align-items`, `flex-wrap`, `gap`); `container` grid → se conserva v3 y sus hijos se migran. Nodos ya atómicos quedan igual. Ids nuevos para los nodos convertidos (`ElementorTreeBuilder`); los v3 conservados mantienen id y ajustes tal cual.
  - Widgets: heading → `e-heading` (`title`, `header_size` h1-h6/span → `tag`, `link`; `div`/`p` → se conserva v3); text-editor → `e-paragraph` uno por párrafo si el HTML sólo tiene `p`, `a`, `span` y texto (S8), si no se conserva v3; button → `e-button` (`text`, `link`; con `selected_icon` → se conserva v3); image → `e-image` (`image` id+url, `image_size` → `size`, `link_to` custom/file → `link`; con `caption` → se conserva v3); divider → `e-divider` con línea en estilo (con texto o icono → se conserva v3); cualquier otro widget → se conserva v3 (S4).
  - Estilos (S5): un estilo local por nodo convertido con variantes `desktop`, `tablet`, `mobile` (sufijos `_tablet`/`_mobile`): tipografía (grupo con `typography_typography` = `custom`: familia, tamaño, peso, alto de línea, espaciado, transformación) y alineación; color de texto (`title_color`, `text_color`, `button_text_color`); `background_color` (sólo fondo clásico); `_margin`/`_padding` y `margin`/`padding` de contenedor; borde (`border_border`, `border_width`, `border_color`, `border_radius`). `__globals__`: color global → variable atómica de color con el mismo nombre si existe, si no el color literal del Kit; tipografía global → valores literales del Kit. Lo no trasladado va a `unmapped`.
  - Validación: el árbol migrado pasa `ElementorTreeValidator`; los widgets v3 conservados se aceptan sólo si son idénticos (id y ajustes) a un nodo de la página original. Tope de nodos `max(200, nodos actuales)` como F3.
  - Contrato entre T2 y T3: interfaz `V3StyleMapper::map(string $widget_type, array $settings): array{styles: array, unmapped: list<string>}` (`styles`: variantes listas para un estilo local del validador); T2 la recibe inyectada y T3 la implementa (`ElementorV3StyleMapper`) con colores/tipografías del Kit y variables inyectables para PHPUnit.
