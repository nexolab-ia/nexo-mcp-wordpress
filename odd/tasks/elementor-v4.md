# Elementor 4 atómico: lectura, creación de páginas (F1 + F2) y reconstrucción de secciones (F3)

Primera entrega del soporte de Elementor v4 (widgets atómicos) en el MCP. Fases acordadas: F1 leer v4 y sistema
de diseño, F2 crear página atómica. Fases posteriores (no abiertas aún): F3 reconstruir secciones, F4 escribir
clases/variables/estilos globales, F5 migrar v3 → v4, F6 datos dinámicos, F7 componentes como datos.

## Specs

- S1. Pedido: «Crea una página completa en Elementor a partir de una descripción, lista para editar».
- S2. Pedido (parte de lectura, F1): «Gestiona clases, variables y estilos globales».
- S3. Decisión: primera fase «F1 + F2: leer v4 y crear página (Recomendado)»: «Base de lectura y la primera capacidad visible: crear una página atómica en borrador desde una descripción.»
- S4. Decisión para «Crea nuevos widgets atómicos registrados en Elementor»: «Componentes como datos, sin PHP (Recomendado)»: «Bloques reutilizables guardados como datos (Components de la v4 o plantillas). Nada ejecuta código nuevo.» (fase F7, fuera de esta entrega; ninguna herramienta escribe ni activa PHP).
- S5. Decisión de destino de escrituras v4: «Copia de trabajo y publicar después (Recomendado)»: «Como el resto del contenido: revisás con get-working-copy-diff y la vista previa antes de publicar.» En esta entrega: la página creada nace como borrador.
- S6. Diseño (del padre, a partir de S1-S5, se ajusta con la evidencia de T1):
  - La IA interpreta la descripción y arma el árbol atómico; el plugin lo valida y lo guarda. Sin generación de contenido en el servidor.
  - F1: `get-page-structure` reconoce los elementos atómicos (`e-*`): tipo, id, texto legible y clases aplicadas. Herramienta nueva de lectura del sistema de diseño (clases globales, variables, colores y tipografía del Kit activo).
  - F2: herramienta nueva que crea una página Elementor en borrador a partir de un árbol atómico. Lista cerrada de elementos y de `$$type` permitidos; nunca HTML/shortcode/código (lista `NEVER`); enlaces con los esquemas permitidos; imágenes sólo por ID de biblioteca; ids nuevos generados por el plugin; tope de nodos y bytes; CSS regenerado. Permisos del módulo de constructores (`builders_tools_enabled`, `mcp:builders`) más `edit_pages`/creación.
  - Si los elementos atómicos (`e_atomic_elements`, que activa `e_opt_in_v4`) no están activos, la creación se rechaza con un error que explica cómo activarlo.

- S7. Diseño de T2 (del padre, con la evidencia de L4):
  - Lectura atómica en `ElementorAdapter::read_nodes()`: un nodo cuyo tipo (`widgetType`, o `elType` si no es `widget`) empieza por `e-` sale con `editable: false`, `reason: "Elemento atómico de Elementor 4: por ahora sólo lectura."`, `text` desde la prop de texto del tipo (`e-heading` → `title`, `e-paragraph` → `paragraph`, `e-button` → `text`; valor `{$$type, value}` con `value` string, o `html-v3` con `value.content.value` string; cualquier otra forma = sin `text`) y `classes` (lista de strings de `settings.classes.value`; si no es lista de strings, sin `classes`). `classes` sólo viaja si no está vacía. Los widgets v3 y contenedores v3 conservan su forma. Contrato fijado por `app/nexo-mcp/tests/ElementorAtomicReadTest.php`.
  - Herramienta nueva de lectura `nexo-mcp/get-design-system` (sin entrada). Salida: `atomic_enabled` (bool, `Plugin::$instance->experiments->is_feature_active('e_atomic_elements')`), `kit_id`, `colors` (system + custom del Kit: `{id, title, color}`), `typography` (system + custom: `{id, title, font_family, font_weight}` con lo que haya), `classes` (clases globales `{id, label}` en su orden, de `Global_Classes_Repository`), `variables` (`{id, type, label, value}` sin las borradas, de `Variables_Repository`). Cada bloque que no exista en la versión instalada (clase ausente) sale como lista vacía, sin error fatal; sin Elementor activo la herramienta responde un error claro. Permiso: lectura del módulo de constructores (mismo toggle/capability/scope que `get-page-structure`).

- S8. Diseño de T3 (del padre, con la evidencia de L4):
  - Herramienta de escritura `nexo-mcp/create-elementor-page`. Entrada: `title` (string, obligatorio), `elements` (árbol atómico, obligatorio, lista no vacía), `slug` (opcional). Cada nodo: `type` (tipo atómico), `settings` (props `{$$type, value}`), `styles` (opcional, mapa de estilos locales `id → {id, type: "class", label, variants}`), `elements` (hijos, sólo en contenedores). Los ids de elemento los genera el plugin; los que mande el cliente se ignoran.
  - Requiere Elementor activo y `e_atomic_elements` activo; si no, error `nexo_mcp_elementor_v4_required` que explica cómo activar Editor V4. Nada se escribe.
  - Lista cerrada de tipos: contenedores `e-flexbox`, `e-div-block`; widgets `e-heading`, `e-paragraph`, `e-button`, `e-image`, `e-divider`. Todo lo demás se rechaza (incluye `e-svg`, por ser vector de código, y cualquier widget v3 o de la lista `NEVER`). Sólo los contenedores admiten hijos.
  - Validación previa propia (clase pura con PHPUnit): forma del árbol, tipos, profundidad ≤ 10, nodos ≤ 200, bytes ≤ 3 MB, claves de `settings` desconocidas para el esquema rechazadas, enlaces (`link.destination` URL) sólo con los esquemas que ya admite `AttributeValue` (https, mailto, tel), imágenes sólo por ID de adjunto existente (nunca URL), ids de estilo y clases con el formato `/^[a-z][a-z-_0-9]*$/i`, y cada clase referenciada en `settings.classes` debe ser un estilo local del mismo nodo o una clase global existente. Después, validación de Elementor (`Props_Parser` con el esquema del tipo, `Style_Parser` para los estilos). Todo error indica la ruta del nodo (p. ej. `elements[0].elements[1].settings.title`) y el motivo; con un error no se crea nada.
  - Creación: `wp_insert_post` de una página en `draft` con el título/slug; `documents->get()`; `set_is_built_with_elementor(true)`; `save(['elements' => árbol])` con el usuario actual, dentro de try/catch; si falla o devuelve false, se borra el borrador creado y se responde el error. Salida: `id`, `status: "draft"`, `preview_url`, `edit_url` (editor de Elementor), `nodes` (cantidad de nodos guardados). Nunca publica.
  - Permiso: escritura del módulo de constructores (`builders_tools_enabled`, `Capabilities::BUILDERS`, scope `mcp:builders`, además de escritura), con `edit_pages`/`publish` no requerido; respeta «Solo revisar» y demás interruptores como las otras escrituras.

- S9. Pedido: «Reconstruye secciones utilizando widgets atómicos de la versión 4». Decisiones: operaciones «Reemplazar, insertar y borrar (Recomendado)»: «Reemplazar una sección por un árbol atómico nuevo, insertar uno antes o después de un nodo, y quitar un nodo. Todo en la copia de trabajo.»; páginas «Cualquier página de Elementor (Recomendado)»: «También páginas v3: Elementor permite mezclar secciones v3 y atómicas, así se puede pasar de a una sección. Lo nuevo siempre es atómico.»
- S10. Diseño de F3 (del padre; T4 lo confirma o corrige con evidencia):
  - Herramienta de escritura `nexo-mcp/edit-elementor-section`. Entrada: `id` (página o su copia de trabajo), `operation` (`replace` | `insert` | `delete`), `node_id` (nodo de referencia), `position` (sólo `insert`: `before` | `after` | `inside`, este último agrega al final de un contenedor), `elements` (árbol atómico nuevo, obligatorio para `replace` e `insert`, prohibido para `delete`).
  - Lo nuevo pasa por `ElementorTreeValidator` y por los parsers de Elementor como en `create-elementor-page`; ids nuevos generados por el plugin; los límites (nodos, profundidad, bytes) se aplican al documento resultante completo.
  - Destino (S5): si la página está publicada (o programada/privada), el cambio va a su copia de trabajo (se crea o se reutiliza la existente, con la misma regla que `update-page`); si ya es borrador, se edita el borrador. El original publicado no cambia hasta publicar la copia; `get-working-copy-diff` la muestra.
  - Reglas de anidado (T4, L12): raíz del documento: sólo contenedores atómicos (`e-flexbox`, `e-div-block`); dentro de una columna v3 (`column`): sólo widgets atómicos (un contenedor atómico ahí Elementor lo descarta en silencio); dentro de una sección v3 (`section`): nada nuevo (sólo admite columnas); dentro de un contenedor v3 (`container`) o atómico: cualquier tipo permitido; dentro de un widget: nada. `insert` con `before`/`after` usa las reglas del padre del nodo de referencia; `inside` las del propio nodo. `replace` usa las del padre del nodo reemplazado. `delete` no puede dejar la página sin elementos raíz. Todo rechazo indica el motivo y no escribe nada (ni crea copia).
  - Guardado (T4, L12): no con `Document::save` (reescribe y filtra el contenido v3 existente), sino empalmando en el árbol decodificado y escribiendo con `ElementorAdapter::save_tree`; antes de guardar se comprueba que todos los nodos no tocados quedan idénticos; el subárbol nuevo se valida con el validador propio y con los parsers de Elementor (como en `create-elementor-page`); los ids nuevos no chocan con los existentes; los límites (nodos, profundidad, bytes) se aplican al documento resultante; se invalida el CSS del post editado; se respalda como las demás herramientas de constructor.
  - Fuera de alcance de F3: pasar `update-node-text`, `update-node-attribute` y `edit-structure` a copia de trabajo (hoy escriben en vivo con respaldo).
  - Salida: `id` (post editado), `draft_of` (si es copia), `preview_url`, `operation`, `node_ids` (ids creados) o `removed` (ids quitados).
  - Permiso: escritura del módulo de constructores y `edit_post` sobre el original; respeta «Solo revisar»; nunca publica.
